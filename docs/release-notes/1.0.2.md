Baesian 1.0.2 keeps your projects page up to date while it's open, and stops the service building a project's state again for every request.

## What's new since 1.0.1

- **Your projects page shows a new card as it's filed.** Each project's inbox at [baesian.dev](https://baesian.dev) updates within a second or two of a card being filed or answered, with no reload. Before, the page checked only as it opened and when its tab came back into view, so a card filed while you were looking at it didn't show.
- **A project that hasn't changed is sent as it was last built.** The service used to work out a project's state from its files every time it was asked, most of a second for a couple of hundred cards, on each open and for each count on your projects page. It now keeps the state it built, in the project's own database, and sends that until the project changes.
- **What's kept is never out of date.** Any change to the project (a card filed, an answer, an agent starting to wait) empties it in the same step, and it's built again two seconds later. A card's text that retention removes is gone from it at once. Nothing new is collected, and the privacy policy is unchanged.
- **The first read after a change still builds the state,** as before; that includes the read that follows your own answer.
- **Your account reads quicker:** its passkeys, emails and projects are read together, where they were read one after another.

No file format changed, and nothing changed in the command line, the plugin's behaviour or your git hooks. The service still serves the 1.0.0 and 1.0.1 command lines.

## Updating

Update the CLI and the plugin together, so the plugin finds its own release on your PATH:

```sh
npm install -g baesian
```

Then the plugin. In Claude Code, from a terminal, then start a new conversation:

```sh
claude plugin update baesian@baesian
```

In Codex, then start Codex's interactive mode and accept its "Hooks need review" prompt:

```sh
codex plugin marketplace upgrade baesian
codex plugin add baesian@baesian
```

Nothing else needs running again. CI pinned to an earlier release by `baesian ci` keeps working; run `baesian ci` again only if you want it on 1.0.2.
