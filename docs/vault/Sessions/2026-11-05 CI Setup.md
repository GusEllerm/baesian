## Goal

Close the hole the linking showed (a commit that re-links the repo to a made-up project could write its own answers from before linking), and make setting up a linked repo's CI one command.

## What was done

- **B-mar8x, CI pins the project** ([[src-verify#In a hosted repo (M9a)]], [[File Formats#The hosted service's proof (M9a)]]):
  - the pin gains a line, `{"type":"project","format":1,"project":"p-…"}` (`PinnedProject`); a pin with keys and no project, or two projects, stops the command, saying to run `baesian ci`;
  - with a pin, the repo's project is the pinned one, and a commit whose config names another fails;
  - the linking commit is found by ancestry, never by date (`recordAtLinking()`), and with a pin once, from HEAD, for every commit checked, so a branch in flight at linking passes when its answers were in the record at linking; two linking commits, none descending from another, fail the run.
- **B-pt52b, `baesian ci`** ([[src-sync#src/ci.ts: setting up CI (B-pt52b)]]): pulls, then prints the service it read the keys from, the pin's lines (the project's, the service's key, the passkeys it signed), read from the live layer only, and the workflow steps; `--github` sets the variable with `gh`; `--json`.
- **B-f2mfb:** `baesian login` links to https://baesian.dev when nobody names a service (`DEFAULT_SERVICE`), and says so.
- **The README's "Use it in a repo"** gains the hosted steps: `baesian login`, the commit it prints, `baesian ci`.
- **Tests:** the re-link with a forged unsigned answer fails under the pin; a backdated commit naming the pinned project on a branch from before the link fails closed; a commit from before the link building on an answer in the record at the linking commit passes; `baesian ci` against the local relay, with gh stood in for; `login`'s default, offline.
