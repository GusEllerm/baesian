# Decision Log

Newest first in each table. Only the user moves an item from **Proposed** to **Accepted**. Process: [[Working Agreement#Decision cards]].

This vault uses D-numbers for the user's decisions and P-numbers for proposals until Baesian can run its own decisions (D21). After that, decisions carry card IDs (D18, D19).

"Decision card (dry run)" means the user answered a real card in the round 5 prototype (`design/explorations/round5/#dryrun`). The answers are kept in `design/dryrun/`, one file per answer, with the cards as shown in `design/explorations/round5/dryrun.js`.

- 2026-10-31 `[agent decision]` M4 step 5a's details ([[Client Build]]):
  - **The client's devDependencies are pinned exactly,** so a build is reproducible.
  - **The API's types are self-contained,** so the client can check its types without Node's: `Status` and `Brief` moved into `src/api.ts` (the store re-exports them), and the ID patterns into `src/schema.ts` (`ids.ts` re-exports them). Nothing changed in behaviour.
  - **The client's security policy is strict:** only the server's own origin, for everything, with no inline styles or scripts. The browser tests check that nothing breaks under it.
  - **The dev server uses port 5317,** and its proxy reads the running server's file. Development only.
  - **The browser tests reuse the unit tests' fixture helpers** (`test/helpers.ts`), and start a real server for each test.

- 2026-10-24 `[agent decision]` The details of M4 step 4's server ([[Local Server]], [[src-server]]):
  - **Verdicts from the client** carry `reviewer` from git's `user.name`, and `client: "web"`.
  - **Presence, the server file, inbox cursors and temporary files never count as a change.** A waiting marker's staleness is computed at snapshot time, and the client re-evaluates it as time passes.
  - **Codes:** 403 for a wrong host or a bad token, 401 when not signed in, 415 for a write that isn't JSON, 413 over 64 KB, and 409, 404 or 400 for a verdict that's stale, about an unknown card, or invalid.
  - **`GET /api/health`** lets a second `serve` check that the first is really answering, before trusting the server file.
  - **The branch-deck race**, found by the four-writer test, is fixed in the store rather than by a lock.

- 2026-10-24 `[agent decision]` M4 step 3's readings of D80, D81 and D90:
  - **D80 covers the reviewer's own answer** (`correction`) as well as the alternative: neither is the proposal the dependents assumed.
  - **A dependent isn't returned** if it was revised, or answered by the reviewer, after the parent's verdict: the new answer was already taken into account. Status is computed, so if the parent's answer changes back, the dependent reopens.
  - **Briefs are computed from the records, like status, and never stored.** Until now, D35's "rework brief" existed only as wording in messages.
  - **D81's brief comes with any change of answer after a resolving one,** including a change to a rejection. It lists every ledger entry from before the change, worded as a lower bound. With no commits, it still says the answer changed.
  - **The waiting marker is removed however `wait` returns:** a verdict, a timeout, or the reviewer away. If the process is killed, the marker is left to go stale, since a killed wait is the case D90 exists for.
  - **The commit gate's delivery of verdicts doesn't carry briefs yet;** `wait`, `inbox` and `show` do.
