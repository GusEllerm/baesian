alternative_then: Notes appear when a person or agent runs a new command, in a commit they choose. The vault can lag the record, and baesian verify could warn in CI when it does.

rationale: It's the git phase every agent and person shares (D27), it puts each note on every branch whose record holds the card, as D43 asks, and nobody has to remember a step.

Writing from the record, in the hook that already updates the record, means a note is always on the branch that holds its card, and two branches write the same bytes. Turning the adapter on writes notes for every decision already made. The details, and the two other moments considered, are in [[Vault Adapter#1. When notes are written]].
