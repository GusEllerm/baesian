proposal: "A personal mode: nothing committed"
proposal_then: "`baesian init --personal` keeps everything in the clone: the record and the link in `.git/baesian/`, the gate in a per-clone hook folder that runs Baesian's block, then the repo's own hooks; instructions from the plugin installed for you, not `AGENTS.md`. Your agents file cards and you answer them on the website as now. Decisions don't travel with the code in git, and CI can't check them. Switching the repo to shared mode later commits the record."
alternative: Shared but optional
alternative_then: "`baesian init` commits as now, but the hook skips quietly where Baesian isn't installed instead of refusing the commit. Decisions travel in git for everyone to see. `AGENTS.md` tells every collaborator's agent to file cards, including those without Baesian, and the change is in the shared repo for others to review."
crux: Should trying Baesian in a shared repo need the collaborators' agreement?
crux_proposal: "No: one person can start alone"
crux_alternative: "Yes: it's the team's repo"
crux_preference: true
crux_fact: "Today `baesian init` writes into committed files: Baesian's block in the hooks (which refuses commits on machines without Baesian, and until it's published nobody else can install it), `.baesian/`, and `AGENTS.md`. The live layer, `.git/baesian/`, is already per clone. CI's `verify` needs the committed record. Several reviewers on one project isn't built."
rationale: Most people who'd try Baesian work in repos they share. Personal mode lets them start without a team discussion, and moves to shared mode once the team wants the record; the alternative still changes what everyone's agents are told.
