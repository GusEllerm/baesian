title: What a merge record says it brought
question: Should the command line record everything a merge actually brought into a branch, including a fast-forward that follows it, or should the panel infer it?

proposal: Record it
proposal_then: The merge record names the tip that landed, and a later fast-forward of the same branch into the same target updates it (or adds a record), checked against git's ancestry when it's written. The panel draws what's recorded, with no guess.
alternative: The panel infers it
alternative_then: The merge record stays as it is, and the panel draws commits made within 60 seconds after a merge as part of it, saying so in their callout.
crux: Should the panel ever draw a merge Baesian didn't record?
crux_proposal: No
crux_alternative: Yes, labelled as inferred
crux_fact: "Found by the loop: git shows f823982 and c15577a were fast-forwards into v1/next, and the commits made 25 s and 17 s later (91e3781, d737b71) reached v1/next through a second fast-forward the merge hook didn't record. The record format changes either way only with the proposal."
rationale: A merge record that misses what landed makes every view built on it guess; the hook already runs at the moment it can see the truth.
