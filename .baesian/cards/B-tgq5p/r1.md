title: Crossings when agents work in parallel
question: When parallel branches can't all sit next to the lane they came from, should rows stay fixed and curves pass over other branches with a gap, or should branches move rows over time so nothing crosses?
doing: taking the branches panel's design loop to a build
topic: client/branches/crossings
deck: branches-view
level: provisional
touches:
  - user-facing
reverse: cheap
proposal: Fixed rows, gaps where curves cross
proposal_then: A branch keeps its row from start to merge. Where a fork or merge must pass another live branch, its curve widens with the rows it spans and the branch it passes shows a small gap. Shortest branches sit nearest their parent; held and unmerged ones go outermost.
alternative: Rows that move
alternative_then: A branch moves to whichever row is free as others start and end, so no curve ever crosses a live branch, but its line steps sideways as you scroll.
crux: Is a straight line per branch worth an occasional crossing?
crux_proposal: Yes
crux_alternative: No
crux_preference: true
crux_fact: "Measured on made-up histories: four parallel worktrees with held branches give 4 crossings with fixed rows, the minimum when their times overlap; six branches alive at once give none. This repo's history has no crossings either way."
rationale: A branch that keeps its line is easy to follow by eye; crossings are rare, marked, and only where branches really ran at once.
