title: Symbols in the command line's output
question: On a terminal, should the command line mark outcomes with symbols (✓ ✗ ! →) as well as colour?
doing: a UX pass over the command line's output, asked for by the user
topic: cli/output/symbols
deck: cli-output
level: provisional
touches:
  - user-facing
reverse: cheap
proposal: Symbols and colour
proposal_then: A headline starts with ✓ (done), ✗ (blocked or failed), ! (needs attention) or → (a next step), in its colour; where the terminal can't show them, ok, x, ! and -> instead. Agents never see either.
alternative: Colour only
alternative_then: Headlines carry their outcome in colour and words alone. Readers who can't tell red from green, or whose terminal shows no colour, rely on the words, which say it anyway.
crux: Is a shape beside the colour worth the extra character on every headline?
crux_proposal: Yes
crux_alternative: No
crux_preference: true
crux_fact: Symbols carry the outcome without colour, which helps colour-blind readers and terminals without colour. They appear only on a terminal, never in what agents read.
rationale: A blocked commit and a passing one look the same today; a ✗ is the one strong signal the audit's proposal adds, and it doesn't rest on colour.
