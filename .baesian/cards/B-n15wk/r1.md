title: How the docs install the CLI
question: Once it's on npm, do the README and setup guide install Baesian's command line globally, or run it through npx with nothing installed?
doing: "planning M10: the install step in the README and docs/setup.md"

reverse: moderate
proposal: npm install -g baesian
proposal_then: the docs' first step installs it once; the git hooks, the plugin and agents find `baesian` on PATH as they do under `npm link` today; updating is the same command; the hooks' fallback points at the installed copy.
alternative: npx baesian, nothing installed
alternative_then: the docs run `npx baesian init`; the hooks it commits, the plugin and AGENTS.md call `npx --yes baesian@<version>` instead of `baesian`; nothing to install, but a run may fetch from npm, and offline it needs a cached copy.
also_considered:
  - "Both: npx for a first try, a global install for daily use"
crux: Should Baesian work on a machine where nothing was installed first?
crux_proposal: "No: install it once"
crux_alternative: Yes
crux_preference: true
crux_fact: "The commit gate runs from git's hooks, outside any agent session. They run `baesian` from PATH, else the fallback `baesian init` recorded: the path of the script that ran it. Run through npx, that path is in npm's cache (~/.npm/_npx/), which npm may clear. The plugin's hooks and MCP server, and agents' own commands, also run `baesian` from PATH. Under nvm a global install belongs to one Node version."
rationale: The gate, the plugin and agents each need a `baesian` they find every time, offline and fast; npx gives neither, and would change every committed hook. A one-line global install is how people already install Claude Code and Codex.

Part of M10's plan, [[Release v1]], sections "Publishing the CLI to npm" and "The docs". Today the docs build the CLI from a clone (`npm run build && npm link`). `baesian ci` prints `npx baesian verify` for CI, which is a separate question (which version CI runs), on its own card.
