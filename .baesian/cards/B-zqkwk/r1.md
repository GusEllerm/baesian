title: Where a project's name is kept
question: Should a project's name be one you type when you approve its first machine, kept on the service, or a label kept only in each of your browsers?

proposal: You name it, on the service
proposal_then: The page that approves a project's first machine asks what to call it, and you can rename it on the website. The service keeps the name with the project, and every device and notification shows it. The CLI never sends the repo's name.
alternative: Only in your browsers
alternative_then: The service knows a project only by its random ID. Each browser or phone you use asks you to name a project the first time it shows it, and keeps the label to itself; notifications get the name from it as they're shown.
also_considered:
  - The CLI suggests the repo's folder name, to edit on approval
crux: Is a name you type yourself all right for the service to hold, given it never collects repo names?
crux_proposal: Yes, I chose it
crux_alternative: No, keep it local
crux_preference: true
crux_fact: The service never collects repo names or URLs (Hosted Service section 6), and knows a project by a random ID like p-7f3kq… (M9d). Notifications say counts and levels only, like "2 cards waiting in baesian (1 hard)" (B-mjf3g). The service builds and sends each push (B-nk97q), and a phone's notification code can look up a label it holds before showing one. With names only in browsers, each new device starts with IDs until you name them there. A typed name is data you give the service, and would be listed on its public page of what it holds.
rationale: One name, typed once, works on the phone, the desktop and in notifications, and it's a name you chose, not one read from your repo. Keeping it off the service would mean naming every project again on every device.
wrong_if: People type their repo's real name, so the service ends up holding repo names anyway, or you'd rather no device but yours knew what a project is.

The website needs a name to show for each project, on its list of projects, its pages and its notifications. The repo's own name is the obvious one, and the one the service has promised not to collect, so either you type a name or no name leaves your devices.

**The option also considered.** `baesian login` could send the repo's folder name as a suggestion for the approval page, where you could change it. It's the most convenient, and it means the service learns repo names by default.
