question: "From 1.0, what does each later 1.x keep working: only Baesian's files and the relay's protocol, or also the commands agents are told to run?"

proposal: Files, relay, and agents' commands
proposal_then: a later 1.x reads every file and trailer, keeps the relay's /v1/ API, and keeps the commands, flags, exit codes and MCP tools that AGENTS.md and the plugin tell agents to use; other output may change.
alternative: Files and the relay only
alternative_then: a later 1.x reads every file and trailer and keeps the relay's /v1/ API; commands, flags and exit codes may change in any release, and repos run `baesian init` again to refresh what AGENTS.md tells agents.
crux: Will agents often follow instructions an older Baesian committed, while running a newer one?
crux_proposal: Yes, often
crux_alternative: Rarely
crux_fact: "`baesian init` commits a block to AGENTS.md naming commands and `baesian wait`'s exit codes (0, 4, 5, 6, 7, 8); updating the command line doesn't rewrite it. The plugin's hooks print the installed command line's own instructions. D108, D156 and D157 already make files versioned from v1. The relay's protocol is versioned in its address, /v1/ (B-7z97x). The MCP server's twelve tools mirror the commands."
rationale: Agents read instructions written by whichever Baesian last ran `init` in the repo, so the commands and exit codes those name are as public as the files; breaking them silently sends agents the wrong way.
