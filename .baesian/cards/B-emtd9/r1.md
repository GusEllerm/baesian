question: Under what name is Baesian's command line published on npm?
doing: "planning M10: publishing the command line to npm"

level: hard
touches:
  - publishes

reverse: one-way
proposal: baesian
proposal_then: people run `npm install -g baesian`; the command stays `baesian`; the hint in the hook block `baesian init` commits (`npm i -g baesian`) and `baesian ci`'s `npx baesian` are right as they are.
alternative: "@baesian/cli, under an npm org"
alternative_then: you make the npm organisation baesian; people run `npm install -g @baesian/cli`; the command stays `baesian`; later packages can share the scope; the hook hint and `baesian ci`'s steps change to the scoped name.
also_considered:
  - baesian, and the @baesian org made too, to hold the name
crux: Will Baesian publish more than one package on npm?
crux_proposal: Not that I can see
crux_alternative: Probably
crux_fact: "On 2026-11-10 `npm view baesian` and `npm view @baesian/cli` both returned 404: neither is taken. `bayesian` is taken (0.0.1). A package can't be renamed once published, and a version number once used is never reused, even after unpublishing. The command's name comes from `bin` whatever the package is called. Whether the npm organisation name baesian is free wasn't checked: that needs a login."
rationale: v1 publishes one package, the command line with the client it serves; the service deploys to Cloudflare and the plugin installs from the repo. An unscoped name is shorter in every doc, hook message and CI step, and matches the command.
wrong_if: A second npm package becomes likely within a year, or someone takes the @baesian scope and confuses people.
