proposal: Login links it too
proposal_then: In a repo with no project, baesian login makes a project ID, writes the service and project into the config, and asks you to approve this machine for it. In a linked repo it only signs the machine in. One command to learn.
alternative: A separate baesian link
alternative_then: baesian link writes the service and project into the config; baesian login only signs a machine in, and in an unlinked repo says to run baesian link first. Putting a repo on the service is a step you take on its own.
crux: Should putting a repo on the service be a step of its own, apart from signing a machine in?
crux_proposal: No, one step
crux_alternative: Yes
crux_preference: true
crux_fact: Each machine's grant is for one project (B-84e0d), so signing in has to name a project. The service creates a project when its first machine is approved, owned by whoever approves it in their browser (M9c). Linking writes the service, the project and the repo's first commit (B-5gnea) into the committed config, a gate fact that needs a card or an ack (B-w4g6c); the command prints the ack. An agent can run either command; approval needs your browser and a passkey check.
rationale: The first sign-in and the link happen together, and the approval page already says a project is being created, so a separate command adds a step without adding a check. The gate fact on the config change keeps linking visible in review.
wrong_if: People link repos by accident when they only meant to sign in, or need to link a repo from a machine that won't sign in.
check: While dogfooding, note each time login links a repo, and whether that was meant.

Hosted Service section 2 says a project is "created on first use by `baesian init` in a signed-in shell, or by a new command that links an existing repo", and leaves the command open. M9c built the service side: the device flow takes the project ID and the machine's name, and approving it creates the project. `baesian logout` revokes this machine's grant and deletes its token either way.
