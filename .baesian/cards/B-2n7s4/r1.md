title: Who a card reaches first
question: When no map names anyone for a card, should it go first to the member running its agent, or to the project's owner, who passes it on?
doing: drafting the proposal for several reviewers per project
topic: reviewers/first-reviewer

level: hard

reverse: cheap
proposal: Whoever runs the agent
proposal_then: "a card is its agent's person's: the account whose machine filed it. It reaches an owner only from a shared machine, or when that person has left. Teammates see it listed, and can answer it themselves once it's decided."
alternative: The project's owner
alternative_then: every card lands with an owner first, who answers it or passes it to a member. One person sees every decision as it's made; the others get what's passed to them.
crux: Should a card reach the person closest to the work first, or one person who sees them all?
crux_proposal: The person closest to the work
crux_alternative: One person who sees them all
crux_preference: true
crux_fact: "Each machine signs in as one account, so the relay knows whose agent filed a card. In DORA's 2019 survey, teams whose changes were approved by a body outside the team were 2.6 times likelier to be low performers, with no evidence of fewer failed changes. Reviewers who know the area review faster and give deeper feedback (a Microsoft study of 873 programmers). On the other side: GitHub stops whoever asked its coding agent for a pull request from approving it, and Linear puts a triage inbox in front of a team, where one person accepts or assigns everything. Either way, the merge gate and code review still show a teammate what was decided on a branch."
rationale: "The person steering the agent has the context, and is usually the one waiting on it. Sending everything through one person makes them the bottleneck the research warns about, and it's the same person every time, which is how volume turns into rubber-stamping. The team still sees every decision: at merge, in review, and on the desk."
alternative_rationale: "Whoever runs the agent asked for the work, so they're the least independent judge of it: GitHub won't let them approve their own agent's pull request for that reason. An owner who sees every card keeps the project's decisions coherent, can't be routed around, and learns where the agents go wrong. For a small team that's a few minutes of one person's day, and it needs no rule about whose agent is whose."
serves: the person who knows the work answers, and nobody is a bottleneck
