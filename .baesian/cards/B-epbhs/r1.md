**Why not the wait itself.** `baesian wait` runs in 100-second slices (D101). Left in the background, each slice that ends would wake the agent just to start it again, and it stops at once when the client says you're away. `inbox --wait` covers every card on the branch at once, has no budget, and ends only when there's something new, which it prints the way `baesian inbox` does.

**In both options** the plugin's `SessionStart` hook brings new verdicts into a new session, and `/baesian` is there to make the agent check when you want it to. Harnesses that don't wake the agent when a background command ends (Codex, as far as is known) get only those.
