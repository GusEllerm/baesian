title: How decision notes are named
question: Should a decision note's file name be its card ID and title, or its card ID alone?
doing: designing the vault adapter (M6, proposal P17)
topic: vault/note-names

level: blocking
touches:
  - schema
  - user-facing
reverse: moderate
proposal: Card ID and title
proposal_then: Files read as "B-3akjw How an answer becomes a rule.md" on GitHub and in the file list. In Obsidian an alias finds a note by its ID, and links come out as [[B-3akjw How an answer…|B-3akjw]].
alternative: Card ID alone
alternative_then: Files are "B-3akjw.md", so a typed [[B-3akjw]] links in Obsidian and in agents' notes. The file list and GitHub show bare IDs; the title shows only inside the note and in the Decision Log's table.
crux: Will people and agents link decision notes by typing the card ID, or find them by name?
crux_proposal: If they find them by name
crux_alternative: If they type the ID
crux_fact: Obsidian resolves a [[link]] by file name only. An alias makes its link picker offer the note and write [[name|alias]] (Obsidian help, Aliases). Notes in this vault cite cards as plain text, such as "decision card B-9tk9m r2". Card titles are neutral and don't name the outcome.
rationale: A name that says what the decision is about is what you scan for on GitHub and in git's output, and the alias keeps finding by ID in Obsidian. The title is neutral, so the name stays right when an answer changes.

The same choice would name rule notes (rule ID and first words, or the rule ID alone). The name uses the card's first revision's title, which never changes, so every branch names a note the same way. See [[Vault Adapter#Path and name]].
