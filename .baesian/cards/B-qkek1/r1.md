question: A commit can change the gate's own settings in `.baesian/config.json` without the gate noticing. What should changing them take?

proposal: Your preferences, with the passkey to loosen
proposal_then: The gate's settings (`gate_ignore`, `gate_schema`, `gate_infra`, `gate_api`) move from the committed config into the preference files, which only the client writes. A change that makes the gate see less is loosening, so it takes your passkey (D163), and CI checks the signed file as it checks your preferences. Until that's built, any change to those keys is a gate fact, as changing the link is (B-w4g6c).
alternative: A gate fact, acknowledged in the commit
alternative_then: The settings stay in the committed config, and any change to them is `infra:.baesian/config.json`, needing a card or an ack, as linking does. An agent can still change them, with an ack it writes itself, but only visibly, in that commit's message and record.
also_considered:
  - Pin the gate settings in CI's protected variable beside the keys
crux: Should an agent be able to make the gate see less, as long as it says so in a commit message?
crux_proposal: No
crux_alternative: Yes
crux_fact: "Tested on 2026-11-05 in a throwaway clone with this repo's real pinned keys: a commit that sets `gate_ignore` to `[\"**\"]` and adds a dependency, with no card or ack, passes `baesian verify`; the same dependency without it fails. Today the gate ignores `.baesian/` except the link's three fields. The setting is per repo and committed, so it applies to every machine and to CI."
rationale: An ack is written by whoever makes the change, so for the gate's own blindfold it records rather than checks. The preference files are already the place where only a person, through the client, decides how much reaches them, with the passkey to loosen; the gate's settings are the same kind of decision.
wrong_if: A repo needs its gate settings to differ by branch, or to change in the same commit as the code they cover, which preference files (one set per repo, live at once) can't do.
check: This repo's history of `gate_schema` changes (`git log -p -- .baesian/config.json`), and whether any came with the code they cover.
