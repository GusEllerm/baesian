proposal: A `baesian ci` command
proposal_then: "`baesian ci` syncs, then prints `BAESIAN_TRUST`'s lines (the service's key, and each passkey key the service signed, from what it just pulled, never from the committed record), the service it read them from, and the workflow steps to paste. With `--github` it sets the repo variable through `gh` after showing it. You run it again after adding a passkey."
alternative: A setup page in the docs
alternative_then: Nothing new to build or keep safe. You copy the service's key from `.git/baesian/trust/` and each passkey's line from where the website showed it, write the workflow steps from the page, and set the variable, as this repo's setup took.
crux: Is a key a command copies from the service as trustworthy as one a person copies from the website?
crux_proposal: Yes
crux_alternative: No
crux_fact: "CI pins keys outside the repo so a commit can't add one that passes forged answers (D142, D159). Either way, every key comes from the service: its own over HTTPS, and passkey keys it signed. The service's address comes from the repo's config, which a commit can change with an ack."
rationale: "Both routes read the same service. The command removes the copying, the hunt for two lines in two places, and the ordering trap: an unset variable reaches verify empty and fails CI, by design. Printing the service it used, and the passkey lines for you to compare with your own, keeps the person's check."
wrong_if: The command can be pointed at another service than the one you meant, and nobody notices before the keys are pinned.
check: Whether it prints the service it read the keys from; try it with the config edited to another address.

This repo's setup on 2026-11-05, for comparison: edit both verify steps in `ci.yml` to pass `BAESIAN_TRUST: ${{ vars.BAESIAN_TRUST }}`; read `.git/baesian/trust/service-relay-1.json` and the passkey key file, put each on one line; compare the passkey line with the copy saved at sign-up; `gh variable set BAESIAN_TRUST < file`; all before `main`'s next push.
