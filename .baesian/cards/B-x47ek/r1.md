proposal: Pin a spare key now
proposal_then: you make a second Ed25519 key and keep its private half offline; `baesian ci` prints its line beside the current key's; if the service's key must be replaced, it switches to the spare and hosted repos' CI keeps passing.
alternative: One key, pinned again if replaced
alternative_then: only the key in use is pinned, as now; replacing it fails every hosted repo's CI on answers the new key signs, until each owner runs `baesian ci` again and updates BAESIAN_TRUST.
crux: If the service's signing key had to be replaced, should hosted repos' CI keep passing without their owners acting?

crux_fact: "D142: CI trusts only the service keys pinned in its settings (BAESIAN_TRUST), outside the repo; a key in the record that isn't pinned fails the run, and a pinned key the record doesn't hold yet doesn't (`pinProblems()`). The service signs with one Ed25519 key, a Worker secret. A key file can carry valid_after and valid_before, and a revocation file ends trust in a key from its time. A spare is only as safe as where its private half is kept."
rationale: Today a replaced key breaks CI in every hosted repo at once, and v1 brings more of them; one spare kept offline turns the likeliest emergency into a quiet switch.
